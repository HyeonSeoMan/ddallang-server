# 무료 클라우드 배포 안내 (포트폴리오·시연용)

대상: 실사용자가 없고 가끔 접속해서 유지되기만 하면 되는 개인 포트폴리오. **내 컴퓨터는 서버가 되지 않는다.** 서버와 DB 모두 클라우드에서 돈다. 계획 문서 PD-16(배포 환경)은 아직 확정 전이므로 이 문서는 사용자 결정에 따른 **개발·시연용 임시 안내**이며, 운영 배포 기준이 아니다.

> 서비스의 화면 이름·요금·무료 한도는 자주 바뀐다. 아래 단계는 일반적인 흐름이고 **화면 문구는 직접 확인해야 한다(이 안내는 실제 가입·배포로 검증하지 않았다).** 요금은 가입 전에 각 공식 페이지에서 확인한다.

## 구성

| 역할             | 후보                         | 비용 | 주의                                                                                                                |
| ---------------- | ---------------------------- | ---- | ------------------------------------------------------------------------------------------------------------------- |
| API 서버(Docker) | Render 무료 웹 서비스        | 무료 | 15분 동안 요청이 없으면 잠들고 깨는 데 약 1분 걸린다. 잠들면 SSE 연결이 끊긴다(프론트가 재연결·재동기화한다).       |
| PostgreSQL 16    | Neon 또는 Supabase 무료 플랜 | 무료 | 한도·일시 정지 정책을 확인한다. 백업은 직접 해야 한다. **Render 무료 PostgreSQL은 30일 뒤 만료되므로 쓰지 않는다.** |

## 지켜야 할 제약

1. **DB는 세션 모드 직접 연결 주소**를 쓴다. 서버가 `LISTEN`을 유지하므로 트랜잭션 모드 연결 풀러(예: Neon의 "pooled connection", Supabase의 transaction pooler) 주소는 쓸 수 없다. Neon은 풀러가 꺼진 직접 연결 문자열, Supabase는 직접 연결 또는 session pooler 주소를 쓴다. 이 조건에서의 동작은 실환경으로 검증하지 않았다.
2. 연결 문자열에 `sslmode=require`가 필요한 DB가 많다. 예: `postgresql://사용자:비밀번호@호스트/DB이름?sslmode=require`
3. 인스턴스는 **1개**로 시작한다.
4. 비밀값(`DATABASE_URL`, `CURSOR_KEY`)은 호스팅의 환경변수(시크릿)에만 넣고, 저장소·채팅·로그에 붙이지 않는다.

## 1단계: DB 만들기

1. Neon(또는 Supabase)에 가입하고 PostgreSQL 16 프로젝트를 만든다.
2. 풀러가 아닌 **직접 연결 문자열**을 복사해 둔다(5단계의 `DATABASE_URL`).
3. 마이그레이션은 서버 컨테이너가 시작할 때 자동으로 적용된다(`prisma migrate deploy`). 따로 할 일은 없다.

## 2단계: 환경변수 값 준비

| 이름           | 값                                                                                                                                                                                                              |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NODE_ENV`     | `production` (Swagger `/api-docs`는 꺼진다)                                                                                                                                                                     |
| `PORT`         | 호스팅이 지정하면 그 값, 없으면 비운다(기본 3001)                                                                                                                                                               |
| `DATABASE_URL` | 1단계의 직접 연결 문자열                                                                                                                                                                                        |
| `CORS_ORIGINS` | 프론트 주소(쉼표로 여러 개 가능). 예: `https://내프론트.example` (스킴·포트까지 정확히, 끝에 `/` 없이)                                                                                                          |
| `CURSOR_KEY`   | 32바이트 난수를 base64로 만든 값. 내 터미널에서 `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`를 실행해 나온 값을 시크릿에 바로 붙여 넣는다. 바꾸면 이전 커서가 모두 무효가 된다 |

선택(기본값이 있다): `DB_LOCK_TIMEOUT_MS`(5000), `DB_STATEMENT_TIMEOUT_MS`(10000), `REQUEST_TIMEOUT_MS`(30000), `DB_POOL_MAX`(10). 무료 DB의 연결 한도가 작으면 `DB_POOL_MAX`를 3~5로 낮춘다. 절전에서 깨어난 DB가 느리면 세 시간 제한을 함께 늘리되 `LOCK < STATEMENT < REQUEST < 3600000`을 지킨다.

## 3단계: 앱 배포(Render 기준)

1. GitHub에 이 저장소가 올라가 있어야 한다(`HyeonSeoMan/ddallang-server`).
2. Render에서 **Web Service**를 만들고 저장소를 연결한다.
3. 런타임은 **Docker**를 고른다(저장소 루트의 `Dockerfile`을 쓴다). 인스턴스 종류는 무료로 둔다.
4. 환경변수에 2단계의 값을 입력한다.
5. 헬스체크 경로가 있으면 `/health`로 둔다(인증·DB 없이 `{"status":"ok"}`).
6. 배포한다. 시작 로그에 마이그레이션 적용과 서버 기동 메시지가 나오는지 본다.

## 4단계: 확인

- `https://<발급된 주소>/health` → `{"status":"ok"}`
- 프론트의 API 주소를 이 주소로 바꾸고, 프론트 주소가 `CORS_ORIGINS`에 정확히 들어 있는지 확인한다.
- 방 만들기 → 참여자 등록 → 거래 → 정산·종료를 한 번 해 본다. 이벤트(SSE)가 바로 오는지도 본다.

## 자주 막히는 곳

| 증상                   | 원인과 조치                                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 기동하자마자 종료      | 필수 환경변수 누락·형식 오류(`NODE_ENV`, `DATABASE_URL`, `CORS_ORIGINS`, `CURSOR_KEY`). 로그의 검증 메시지를 본다. |
| 마이그레이션 실패      | 풀러 주소를 쓴 경우가 많다. 직접 연결 주소와 `sslmode`를 확인한다.                                                 |
| 프론트에서 CORS 오류   | `CORS_ORIGINS`가 프론트 주소와 한 글자라도 다르다(스킴, 포트, 끝 `/`).                                             |
| 첫 요청이 매우 느림    | 앱이 잠들었다가 깨는 중이다(무료 플랜). 잠시 뒤 다시 시도한다.                                                     |
| 실시간이 끊겼다 이어짐 | 앱·DB 절전이나 재시작이다. 프론트의 재연결·재동기화로 복구된다.                                                    |
| 이벤트가 오래 지연됨   | 프록시가 SSE를 버퍼링하는지 확인한다(서버는 `X-Accel-Buffering: no`를 보낸다).                                     |

## 하지 않는 것

- 운영(실사용자) 배포 기준의 백업·모니터링·다중 인스턴스 검증은 하지 않았다.
- 이 이미지는 로컬에서 빌드·실행해 보지 않았다(사용자 결정). 첫 클라우드 빌드가 실패하면 빌드 로그를 보고 고친다.
